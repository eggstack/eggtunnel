## 1. Objective

Reduce the remaining runtime, transport, configuration, feature, and maintenance concentration visible after the published 0.2.0 line without changing Eggtunnel wire semantics, supported transport behavior, public Rust method semantics, or the narrow Eggtunnel/Eggress ownership boundary.

The milestone should leave the runtime easier to review before any further protocol or authorization evolution. It is intentionally a behavior-preserving structural pass.

## 2. Why this milestone is dependency-ready

M001-M013 are closed and 0.2.0 is published. The current architecture has stable tests, feature-slice CI, sustained qualification, and downstream-shaped embedding evidence. The next maintenance defects are concrete in the repository rather than speculative:

- `crates/eggtunnel/src/server.rs` remains roughly 1.5 kLOC and owns transport accept, TLS/mTLS/QUIC/WSS setup, handshake admission, authentication throttling, Session registry, service lifecycle, pending correlation, data-path admission, relay orchestration, and drain;
- `crates/eggtunnel/src/client.rs` remains roughly 1.4 kLOC even after M010, with separate TCP/WSS and QUIC reconnect drivers duplicating retry/session bookkeeping;
- client endpoint validation/parsing is split between `valid_endpoint` and `split_endpoint`, while CLI validation contains another endpoint parser;
- Cargo `quic` and `websocket` features currently imply both client and server roles, so a client-only optional-transport embedder compiles unnecessary server code;
- GitHub Actions are version-tag referenced and the repository has no automated dependency-update configuration;
- architecture prose still contains the inaccurate statement that the server never learns the client `TcpTarget`, while the canonical specification and wire DTO deliberately transmit it as non-authoritative bounded metadata;
- planning control surfaces contain residual pre-publication M012 wording.

No new networking capability is required to correct these issues.

## 3. Invariants that cannot regress

- Wire protocol remains version 1.0 with message IDs 1-14 and current DTO semantics.
- Existing 0.2.0 public Rust constructors, builders, handles, snapshots, and transport behavior remain source-compatible unless a strictly additive API is required for feature slicing.
- The generic byte data plane remains owned by `eggress-relay`; no local proxy/relay replacement is introduced.
- TCP/TLS, mTLS, QUIC, WSS, and outbound-proxy semantics remain those documented for 0.2.0.
- The minimal `client,tls` feature slice remains free of server, QUIC, WebSocket, outbound-proxy, and pproxy reverse-protocol dependencies.
- No custom TCP multiplexing, general proxy abstraction, global runtime, or global tracing subscriber is introduced.
- All queues, tasks, handshakes, sessions, Services, pending correlations, and active connections remain finitely bounded.
- ConnectionId single-use/session/service binding and cancellation/teardown behavior remain unchanged.
- Secret-bearing values remain redacted and private-key/token buffers retain current best-effort zeroization behavior.
- M014 must not implement protocol negotiation, concurrent registration correlation, Principal/auth-provider policy, UDP, federation, ACME, persistence, or release-version changes.

## 4. In scope

- server runtime decomposition along existing ownership boundaries;
- unification of duplicated client reconnect/session-supervisor behavior;
- one internal endpoint parse/validation representation for client runtime use;
- role-specific optional transport feature slicing while preserving existing umbrella feature compatibility;
- repository maintenance/supply-chain automation improvements that do not change release semantics;
- planning/documentation reconciliation identified by the post-0.2 audit;
- public-surface audit of currently orphaned types such as `ServiceSpec`, without an unnecessary breaking removal;
- full behavior-preserving regression qualification.

## 5. Out of scope

- new wire messages or capability semantics;
- changing `RegisterService`, `Error`, `Drain`, or dynamic registration concurrency;
- multi-tenant authentication or per-Principal policy;
- new transports;
- changing supported release targets;
- Eggpack/Eggup cutover;
- a new daemon control protocol or status socket;
- performance tuning not justified by a measured regression;
- public API cleanup that requires removing 0.2.0 names.

## 6. Required production changes

### A. Server responsibility decomposition

Split `server.rs` into a small top-level coordinator plus private modules with stable ownership. Exact filenames are implementation-owned, but the result should make these concerns independently reviewable:

- server config/profile validation and TLS/mTLS construction;
- transport accept/admission for TCP/WSS and QUIC;
- authenticated Session registry/lifetime ownership;
- authentication throttling and Principal attachment;
- control-loop Service registration/unregistration and drain;
- Pending Connection/DataHello correlation;
- service listener accept and relay-task ownership.

Do not create a broad generic proxy trait. The abstraction boundary is Eggtunnel Session establishment and transport adaptation, not arbitrary forwarding.

The TCP/WSS and QUIC accept loops should share lifecycle/admission helpers where semantics are identical while preserving transport-specific pre-auth behavior.

### B. Client reconnect/session-supervisor consolidation

Replace duplicated outer behavior in `reconnect_loop` and `quic_reconnect_loop` with one private reconnect/session supervisor.

The shared owner must cover:

- desired-Service state retention;
- disconnected command handling;
- attempt accounting;
- retry delay/jitter progression and reset;
- terminal authentication/authorization handling;
- Session counter/bind cleanup;
- invocation of the existing authenticated Session loop.

Transport-specific code should own only establishment/closure and creation of the data-path transport object. It must not become a public trait surface or general stream-multiplexer abstraction.

TCP/TLS and WSS may remain one establishment family; QUIC may use a private adapter/state object where connection reuse is required.

### C. Canonical internal endpoint representation

Within the library, replace the separate endpoint shape check/split helpers with one parse result that validates:

- DNS-like host text or IPv4 text;
- bracketed IPv6 literals;
- required nonzero `u16` port;
- no whitespace/control-character ambiguity.

Keep `ClientConfig.server_addr: String` source-compatible for 0.2 consumers. Parsing may remain private and cached only for startup/session establishment.

The CLI-specific resolution cleanup belongs to M015, but M014 should expose enough canonical library validation that the CLI does not need to duplicate library semantics later.

### D. Optional-transport role slicing

Add role-specific optional transport slices so downstreams can compile a QUIC or WSS client without server runtime code.

A compatible direction is:

- retain existing `quic` and `websocket` umbrella features for callers that rely on their current role-enabling behavior;
- add additive client-only/server-only feature names, or equivalent additive aliases, that isolate the role-specific code/dependency graph;
- update cfg boundaries so client-only optional transport builds do not compile server runtime modules;
- extend feature-slice CI and minimal dependency guards accordingly.

Do not silently redefine the meaning of an existing published Cargo feature if doing so would break a caller that selected that feature by itself.

### E. Public surface hygiene

Audit `ServiceSpec` and other exported but runtime-unused types.

For M014:

- do not remove a published 0.2.0 symbol merely because it is currently unused;
- either document its intended role/reservation, wire it to an existing public policy surface without semantic expansion, or deprecate it with a clear migration path;
- defer any Principal-policy-specific use to a future authentication/authorization ADR.

Record the disposition in the closure evidence.

### F. Repository maintenance and supply-chain hygiene

Without changing the release artifact contract:

- pin third-party GitHub Actions to immutable commit SHAs where practical while retaining comments identifying the human-readable upstream release;
- add Dependabot or an equivalent checked-in dependency-update mechanism for Cargo and GitHub Actions, with cadence chosen to avoid noisy daily churn;
- retain `cargo audit`, `cargo deny check licenses`, MSRV, rustdoc, feature-slice, and minimal-dependency gates;
- retain exact Eggress pins unless a separately reviewed dependency update is performed and all transport qualification passes.

Do not combine an Eggress version upgrade into this structural milestone unless required to fix a demonstrated blocker.

### G. Planning and documentation reconciliation

Correct control-surface drift introduced around 0.2.0 publication:

- M012 is closed as release-candidate qualification;
- M013 is the closed publication event;
- the current published line is 0.2.0;
- M014 is the current executable milestone.

Correct architecture/security wording so it states that the server receives the bounded `TcpTarget` field in RegisterService but does not treat it as authority and never selects/rewrites the actual client connector target.

Do not change the wire field in this milestone.

## 8. Failure, cancellation, and restart semantics

Structural movement must explicitly preserve:

- cancellation during connect, TLS/WSS/QUIC handshake, auth, registration, pending DataHello, target connect, and relay;
- authentication/authorization failures as non-retrying terminal Session outcomes where currently specified;
- reconnect after transport/protocol disconnection with bounded jittered backoff;
- counter/bind cleanup before the next Session generation;
- shutdown interrupting retry sleeps and transport waits;
- server shutdown stopping new admission before bounded drain/cancellation;
- session teardown releasing listeners, pending correlations, permits, and child tasks;
- QUIC connection replacement invalidating stale streams/session correlations;
- WSS close semantics and current non-equivalence to TCP half-close.

## 9. Required focused tests

At minimum add or retain tests proving:

- shared reconnect supervisor produces the same backoff reset/progression for TCP/TLS, WSS, and QUIC;
- authentication/authorization failure does not accidentally enter the generic reconnect path;
- disconnected register/unregister semantics are unchanged;
- endpoint parser accepts DNS/IPv4/bracketed IPv6 and rejects malformed/zero-port/whitespace cases;
- role-specific client-only QUIC and WSS slices compile without server module/dependency leakage;
- existing `quic`/`websocket` umbrella feature selections still compile the prior public profile surface;
- server handshake/session/service/pending counters converge after success, failure, saturation, cancellation, and shutdown;
- TCP/TLS, mTLS, QUIC, WSS, and outbound-proxy integration tests remain behavior-equivalent;
- target metadata is not used by the server to choose the client-side destination.

## 11. Compatibility and migration effects

- No wire change.
- No crate version change required by the milestone itself.
- Existing published Rust names and existing `quic`/`websocket` umbrella features remain usable.
- Additive role-specific feature names are permitted.
- Internal module/file paths are not compatibility surfaces.
- Documentation corrections may narrow inaccurate claims but must not silently reduce an evidence-backed support claim.

## 12. Acceptance criteria

M014 may close only when:

- server and client lifecycle responsibilities are materially less concentrated and duplicated;
- TCP/WSS/QUIC reconnect/session behavior remains qualified;
- minimal and role-specific embedding dependency graphs are executable in CI;
- no new general proxy/relay abstraction duplicates Eggress;
- endpoint parsing has one internal semantic owner;
- planning and target-metadata documentation are truthful;
- public-surface disposition is recorded without an unjustified break;
- repository supply-chain automation is improved without weakening audit/license/release gates;
- no unresolved high/medium correctness, security, lifecycle, or dependency finding remains;
- exact-head hosted CI passes.

## 13. Stop conditions

Stop and require a new ADR or separate plan if implementation appears to require:

- changing wire message meaning or negotiated compatibility;
- changing the authentication trust model;
- removing a published public Rust symbol or redefining an existing Cargo feature incompatibly;
- importing a broad Eggress facade/reverse protocol;
- adding a custom multiplexing/data plane;
- changing the supported release platform contract.
